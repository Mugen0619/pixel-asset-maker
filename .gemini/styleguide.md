# Geminiレビュー観点 — PIXEL-ASSET-MAKER(ドット絵・ゲーム素材自動生成アプリ)

GitHub ActionsのGeminiによるPR自動レビュー(`.github/workflows/gemini-review.yml`)が参照する、レビュー観点のまとめ。
プロジェクトの全体像・仕様は `PROJECT_CONTEXT.md`、判断の理由は `decisions.md` を見ること。このファイルには、それらと重複しない「何を確認するか」だけを書く。

## 正確性
- 明らかなバグ、ロジックの誤り、想定外の動作がないか。
- エラー処理の不足がないか。想定外の値に気付けるようになっているか。

## 使用技術に固有の観点
技術構成はまだ確定していない(`PROJECT_CONTEXT.md` 6章は「候補」)。確定後に、言語・フレームワークに固有の確認点をここに書く。
- それまでは、「候補」「未決定」の技術を、決定済みとして導入する変更になっていないかを確認する。

## このプロジェクト固有の観点
- APIキーなどの秘密情報が、ブラウザに届くコード(フロントエンド)に含まれていないか。
- 費用が発生する変更(有料サービス・外部APIの呼び出しの追加)が、`decisions.md` の判断なしに入っていないか。
- AI画像生成の部分と、手動編集の部分が、互いに依存しすぎていないか(Decision 003)。

## プロジェクト設計・スコープ
- `PROJECT_CONTEXT.md` の仕様、`decisions.md` の判断と矛盾していないか。
- `PROJECT_CONTEXT.md` で「含めない」「実装しない」「未決定」とされている機能が入っていないか。
- 関連Issueの範囲を超える変更(ついでのリファクタリング、無関係なファイルの変更、指示にない機能・演出の追加)がないか。
- 最初に完成させる範囲に対して、不要な複雑化・過剰な汎用化がないか。
- 仕様が変わる変更なのに、`PROJECT_CONTEXT.md` / `decisions.md` が更新されていない場合は指摘する。

## セキュリティ / GitHub Actions
- APIキー等のSecretが、コード・ログ・PRコメントに出ていないか。`.env` 等をコミットしていないか。
- workflowの `permissions` が必要最小限か(不要な `contents: write` 等がないか)。
- `pull_request_target` など、fork PRのコードをSecret付きで実行する危険な構成になっていないか。
- PRタイトル・本文などの外部入力を、`run:` の中で `${{ }}` として直接展開していないか(環境変数経由で渡す)。
- 使用するActionがコミットSHAで固定されているか。

## テスト / CI
- 既存のテスト(`.github/workflows/ci.yml` / `.github/scripts/ci-test.sh`)を壊す変更になっていないか。
- 既存の機能への回帰(以前動いていたものが動かなくなること)のリスクがないか。
- 変更内容に対して、確認方法(手動確認の手順やテスト)がPR本文に示されているか。
